# GitView licensing and third-party notices

## Project grant and review status

GitView's original project code and original repository documentation are licensed **GPL-3.0-only**, not GPL-3.0-or-later. [LICENSE](LICENSE) is the unmodified GNU GPL version 3 text from [the Free Software Foundation](https://www.gnu.org/licenses/gpl-3.0.txt); the project's version choice is stated here and in npm/Cargo metadata, not inferred from the license's example application boilerplate.

This is **local source-publication preparation, not permission to publish, a legal opinion, or installer certification**. Third-party code, fonts, artwork and adapted policy text retain their own upstream rights. The root GPL grant does not establish ownership of unidentified assets or relicense OFL fonts. Publication readiness requires a freshly regenerated inventory and a passing strict gate for the current dependency and asset selection; the remedies below do not grant rights in removed or replaced components.

## Reproducible evidence

- [licenses/inventory.json](licenses/inventory.json) covers the locked npm and Cargo dependency selections, including optional/foreign-platform packages and locally patched dependencies. Registry entries record exact version, archive URL and lock integrity/checksum; local entries record original archive checksum, complete patched source-file hashes and provenance. npm links are validated against their real local manifest and inventoried once at their physical lock record. All entries retain declared/selected licenses, dependency scope and notice paths with SHA-256 hashes; the check output reports current package counts.
- [licenses/asset-provenance.json](licenses/asset-provenance.json) records source/version/license evidence for asset groups and adapted policy text, including the original View V branding and its generated native exports.
- [licenses/supplemental-sources.json](licenses/supplemental-sources.json) records exact-version exceptions and primary-source notice URLs for packages that omit standalone notices from their published archive. It also records same-version parent-notice relationships for platform build-tool packages. Those relationships do not imply that every component embedded in a prebuilt tool binary has been certified.
- `licenses/texts/` preserves upstream LICENSE, COPYING, COPYRIGHT, NOTICE and AUTHORS files byte-for-byte, including nested vendored notices, `ThirdPartyNotices.txt` and bundled `*.js.LICENSE` / `*.js.LICENSE.txt` sidecars, plus identified source copyright/dedication excerpts. Playwright's third-party inventory and each bundled component's legal sidecar are retained, not just its wrapper license. Empty legal evidence fails closed. Original legal attribution is retained verbatim, including upstream contact details; no private GitView operational configuration is included.

The inventory hashes both lockfiles, licensing inputs/manifests, asset provenance inputs, all copied `src/assets` and native icon files, repository-local skills, adapted policy, the notice summary, auditor source, and every retained legal text. It records all Cargo target predicates and resolved features. Cargo scopes are conservative reachability through the all-platform metadata graph: normal/runtime, host build/proc-macro, and development/test can overlap. Metadata features include development/test unification, so this is not an exact production linker bill of materials. npm distinguishes runtime from development/build/test; **Material Icon Theme is a development dependency whose icon artwork is nevertheless bundled at runtime**.

The source snapshot also covers complete `vendor/` and `src-tauri/vendor/` trees, patch manifests, `scripts/vendor-patches.mjs`, the GLSL replacement plugin and Vite configuration. Local dependencies are never silently omitted because Cargo has no registry source or npm has a link instead of an archive URL. Both refresh and strict checks independently compare the approved native backports and the diagnostic CommonJS adaptation against pinned original archives, rather than trusting self-declared patched hashes alone.

From the repository root:

```sh
node scripts/check-licenses.mjs
node scripts/check-licenses.mjs --check
node scripts/check-licenses.mjs --inventory-only
```

No arguments defaults to `--check`. The first two commands are the strict, read-only gate: exit `0` requires complete current integrity and no unresolved/unsupported licensing or asset evidence; exit `1` means drift or an unresolved licensing block. `--inventory-only` verifies recorded integrity but permits reported unresolved rights; it **never reports publication clearance**. Exit `2` means invalid arguments, unreadable/invalid inputs or unavailable audit prerequisites, never a pass. Selected licenses must match the admitted policy derived from declared licenses and explicit mixed-source exceptions; nonempty arbitrary SPDX text is not accepted. MPL secondary-license incompatibility markers also block clearance.

Checks require installed locked npm dependencies for XML parsing through JSDOM, `tar`, and `curl`. The exact original `why-is-node-running` archive is fetched for independent source comparison; native originals are read from Cargo's registry cache, or fetched over HTTPS when absent. Unavailable sources fail closed. The grammar check independently parses the retained GLSLX XML and permits only the three documented identity changes in the derived JSON; proving actual app/worker replacement remains a separate build/runtime obligation.

To regenerate evidence after an intentional dependency/assets change:

```sh
node scripts/check-licenses.mjs --refresh
node scripts/check-licenses.mjs --check
```

Refresh additionally requires Cargo, `unzip`, HTTPS access to npm/crates.io and pinned GitHub/Mozilla/GNU sources, and Cargo registry archives (Cargo metadata fetches missing crates). It does not install npm dependencies, execute dependency install scripts, change versions, compile, run tests, or publish. It verifies exact npm archive integrity, Cargo archive checksums and approved vendored derivations, downloads and compares the Catppuccin release subset, compares the GLSLX source and MIT grant with their pinned primary source, and compares GPL text against the authoritative canonical digest. It writes generated evidence and legal texts; successful regeneration **is not licensing clearance**. Review changed notices, version-specific selections and exceptions before relying on the strict check. A new version without a matching exception is not silently grandfathered. Obsolete notice directories can be removed only after reviewing the corresponding dependency removal; refresh preserves existing legal material rather than deleting unreviewed files.

## Native, embedded and platform-dependent components

- **SQLite:** `rusqlite` 0.40.2 selects `bundled`, and `libsqlite3-sys` 0.38.2 includes SQLite **3.53.2**. The actual SQLite copyright-disclaimer/blessing excerpt is retained alongside the Rust wrapper's MIT license. [SQLite's authors dedicate deliverable SQLite code and documentation to the public domain](https://www.sqlite.org/copyright.html); this does not mean every build script/optional extension uses those same terms. `sqlcipher/LICENSE` shipped in the crate is preserved, but SQLCipher features are not selected. Optional `sqlite-wasm-rs` / `rsqlite-vfs` entries and their notices are inventoried even though they are not the desktop SQLite implementation. Optional cipher/extensions and future feature changes require their own review, not blanket public-domain treatment.
- **Dual licensing:** where a crate permits MIT OR Apache-2.0, this inventory chooses MIT and preserves both supplied texts. Historical Cargo slash notation is normalized only for known admitted alternatives. Alternatives involving LGPL choose an available permissive branch, not LGPL by default. `dpi` requires Apache-2.0 **AND** MIT; both remain. `target-lexicon` retains Apache-2.0 **WITH LLVM-exception**, including the actual exception, not plain Apache text.
- **Brotli:** `brotli` requires BSD-3-Clause AND MIT. `brotli-decompressor` 6.0.1's historical `BSD-3-Clause/MIT` string is not treated as permission to drop BSD obligations: its Dropbox code has BSD terms and `src/context.rs` carries an original Google MIT copyright/header. Both sets of notices and the embedded Google attribution are preserved, selecting **BSD-3-Clause AND MIT**.
- **Unicode:** Unicode-3.0 notices are retained for ICU/Unicode data crates. `unicode-ident` combines a selected MIT branch with Unicode-3.0; keep both. The root GPL grant does not erase data copyright notices.
- **Windows discovery helper:** `vswhom-sys` 0.1.3 compiles `ext/vswhom.cpp` on Windows. The [original helper at the crate's pinned source commit](https://raw.githubusercontent.com/nabijaczleweli/vswhom-sys.rs/086e3af37e81051057257dfde855ed58a777fb0f/ext/vswhom.cpp) credits Jonathan Blow, dated 31 August 2018, and releases it under MIT. Its original header is retained alongside the complete wrapper MIT grant and nabijaczleweli copyright; wrapper-only attribution does not replace the embedded helper's notice.
- **MPL-2.0:** full notices are retained for `cssparser`, `cssparser-macros`, `dtoa-short`, `option-ext` and `selectors`. Archived Rust sources were checked for the “Incompatible With Secondary Licenses” marker; none was found. [MPL's GPL secondary-license rules and source-availability obligations](https://www.mozilla.org/en-US/MPL/2.0/FAQ/) apply; source URLs/checksums for these exact versions are in the inventory. A later incompatible marker would block this selection. Any distributed executable still needs recipients informed how to obtain corresponding MPL source and any modifications.
- **Platform crates and system libraries:** Windows import-library, WebView2 binding, Android/JNI, Apple/Objective-C and Linux GTK/WebKit bindings are included even on the current host. Their notices cover their own Rust/source components, **not all platform SDKs or OS libraries**. The same-version winapi 0.4.0 GNU import-library manifests and colocated MIT/Apache notices were verified against pinned authoritative upstream source. Linux GTK/WebKit/system libraries, Apple framework/WebKit components and Windows WebView2 runtime/installer dependencies require the actual target's runtime/distribution evidence. They are not pinned as complete OS components by Cargo.lock. Do not infer an installer redistribution license from a permissive Rust binding license or from this source review.
- **Build tools:** complete available upstream and nested distribution notices are preserved for Vite, Rollup, TypeScript, esbuild, Tauri CLI and other tooling. Platform binary packages that omit texts refer to their locked same-version parent notices with an explicit provenance explanation. Those executable tools are not packaged as GitView app assets. Redistributing prebuilt tooling, compiler/standard-library code or tool-embedded native libraries would require a separate artifact-specific license closure; this audit does not certify such redistribution.
- **Syntax highlighting:** Shiki 4.4.3 wraps independently sourced TextMate grammars and themes. Original tm-grammars 1.32.3 and tm-themes 1.12.3 notices are bundled unchanged; GitHub Light, GitHub Dark, Catppuccin Latte and Solarized Light retain their original MIT grants. YAML/TOML retain the pinned TextMate bundle grants as well. The inlined regex WASM matches the integrity-verified vscode-oniguruma 1.7.0 archive; Microsoft's MIT wrapper and K. The collector checks its exact source/license and XML-to-JSON derivation; source snapshot hashes include the app/worker replacement configuration. Do not distribute raw package archives/node_modules or an artifact that bypasses that replacement based on this limited asset review.
- **Local GTK3 backports:** `glib` 0.18.5, `glib-macros` 0.18.5 and `gtk3-macros` 0.18.2 retain their actual original versions and complete original MIT notices. `src-tauri/vendor/patches.json` identifies original checksums, all patched file hashes and exact upstream fix evidence. The independent patch verifier permits only the reviewed GLib pointer-mutability backport and migration of macro diagnostics to the already-required `syn` 2 `Error` APIs; no `proc-macro-error` fork is selected. It does not treat absence from a registry vulnerability scan as clearance. License evidence does not establish maintenance status: the final dependency selection must independently pass the current advisory policy.

Known permissive licenses selected here are compatible with combining their covered code into GPLv3 software while retaining their conditions; Apache 2.0 compatibility is with GPLv3, not GPLv2-only. See the [FSF's primary license compatibility guidance](https://www.gnu.org/licenses/license-list.html). ## Distribution and corresponding source

`src-tauri/tauri.conf.json` maps `LICENSE` to `legal/LICENSE`, this document to `legal/THIRD_PARTY_NOTICES.md`, and the complete `licenses/` directory to `legal/licenses/` using [Tauri bundle resources](https://v2.tauri.app/reference/config/#bundleconfig). These legal files are therefore configured for native resource retention without changing application behavior. The actual location and inclusion must still be inspected in each built distributable; no installer was built or certified as part of this source-preparation review.

A future binary distributor must satisfy GPLv3 corresponding-source and applicable installation-information obligations, preserve all relevant notices, provide required MPL source access, and verify the actual target's bundled runtime/SDK/system components and asset rights. A GitHub source repository URL alone is not an automatic GPLv3 binary compliance mechanism. Do not ship installers or relabel unidentified content on the basis of this document.
