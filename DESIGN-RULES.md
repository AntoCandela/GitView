# GitView UI design rules

1. **Auto-K app surface is the default visual source.** Cream uses warm cream, navy ink and teal action from the Auto-K frontend; alternative palettes retain those semantic roles with their own accessible colors. Tokenize colors, borders and radius roles in `src/style.scss`. Use subtle borders on functional controls, badges and structural edges; avoid a border on every repository row or decorative card framing.
2. **Auto-K typography and spacing.** Use self-hosted Geist for UI and headings, Geist Mono for metadata. Use a 4px base spacing scale; favor 8px and 16px gaps in the workspace. Fonts and icon dimensions can differ for legibility.
3. **Controlled corners and elevation.** Detail badges use 4px corners, controls 6px, panels 8px. Use no decorative shadows; the only shadow is a small functional tooltip elevation. Focus needs a visible palette-accent outline.

4. **View V is the selected identity.** `scripts/generate-brand.mjs` owns its geometry and SVG masters. Use the shared `Brand` primitive with palette-owned ink/accent colors: one compact toolbar mark in a selected repository, or a full lockup in the centered empty state, never both. The sidebar toggle remains the first header control. Keep the active workbench full-bleed; do not add branding rails, cards or repeated labels. Native icons use the Cream/navy/teal master; the favicon adapts to light/dark browser appearance.

## Workspace direction

- Default to three full-bleed panels: old/new file comparison spans the top; compact changed-file hierarchy and Git commit-ancestry graph sit side by side below. File list, graph and comparison scroll independently. Comparison source panes share vertical position; Scroll keeps independent horizontal positions, while Wrap aligns variable-height rows.
- The top-right header layout menu uses reusable radio controls to offer all six assignments to top, bottom-left and bottom-right slots. Changing layout preserves mounted panels, file selection and reading state; layout is an in-session UI choice.
- Both the row divider and lower-panel column divider are draggable and keyboard-resizable, with visible focus and bounded minimum space. Keep the branch/worktree chooser within the graph's current width and height in every slot.
- The graph toolbar shows the branch name only. Its chooser lists all repository-local branches in one flat list, with the current worktree's branch first. Use a checkmark for that branch, a worktree icon for branches checked out elsewhere, and a branch icon for branches not checked out anywhere. Clicking a branch checked out elsewhere opens its existing worktree, changing GitView's active directory and history without checking out files; identify the destination and action in its accessible name and tooltip. Clicking the current or an unchecked-out branch views its history only. There are no row chevrons, nested branch groups or separate folder buttons. Detached worktrees remain accessible below a divider, with an explicit detached label. Worktrees whose local branch ref is unavailable, or additional checkouts of a branch already represented in the list, also retain explicit navigation rows below the divider; prefer the current checkout when a branch is checked out more than once. Disable unavailable navigation rather than silently changing it into history browsing. Keep 8px between search and the first choice, with equal horizontal insets and room for the focus ring. Search matches branch names and worktree labels without changing history or directory. Reuse the graph snapshot's exact local-branch color mapping; detached or snapshot-absent branches remain neutral. Branch names are semibold in the toolbar, picker and graph reference summaries/details. Keep the current-worktree checkmark distinct from viewed-history selection, and explain differing viewed/working branches through accessible tooltip context rather than permanent header text. Branches are shared repository refs, not worktree-owned collections.
- Order branch choices by type: current branch, unchecked-out branches, then branches checked out elsewhere; sort names alphabetically within each type. Other-worktree rows retain current-checkout precedence, followed by attached and then detached destinations, alphabetically by label. Keep the list flat. Hover and keyboard focus show a compact structured tooltip: checkout state, colored icon and full name, labeled worktree/branch details where applicable, then a separated action and its effect on working directory/history. Navigation-disabled rows explain that limitation. Suppress the toolbar tooltip while its picker is open.
- Clicking a commit expands its actual changed-file hierarchy inline, reusing the sidebar's shared directory/file components and status markers. Clicking a committed file opens its selected parent-to-commit comparison in the shared preview, never current working bytes; roots have an absent old side and merges honor the parent selector. Preserve ancestry lines through the expanded space.
- Use a full-bleed workspace: zero outer padding/margins, dense 28px file rows and compact functional toolbars. No Workspace eyebrow, oversized repository heading, visible filesystem-path block, static location-status panel, duplicate in-app brand, icon rail or explanatory chrome.
- Repository management lives in a compact selector/disclosure. Model its searchable repository list on Auto-K's **Design Specs document-list pane**, not its global navigation sidebar. Keep **Open repository** in that disclosure's toolbar and preserve inline rename/removal controls. Selection, Escape and outside click dismiss the disclosure without swallowing a menu/editor's own dismissal.
- Center only the repository selector in the app header. Keep the branch/worktree chooser in the Git graph header. The collapsible workspace sidebar contains the complete current working repository's files, not another repository-management surface; reuse the shared Tree/List switch, global/nested folder controls, status markers and icon themes. Collapsing it preserves the selected preview and directory expansion; narrow windows use an overlay without shrinking the three workbench panels.
- In both files headers, group the global Expand all / Collapse all control immediately left of the Tree/List switch at the right edge. Keep the pair together when narrow headers wrap; repository refresh remains beside the count.
- Window long file lists and history rows without changing their logical keyboard order or resetting offscreen interaction state. Working-tree sticky folder rows must match their pane's opaque background, not introduce contrasting folder blocks. Repository discovery is progressive: label partial counts explicitly, preserve access to ignored files, and never present bounded or failed loading as a complete tree.
- Keep repository names and branch badges compact. Keep full paths and ref names in keyboard- and hover-accessible tooltips, not widened rows. Preserve soft selection without a left stripe. Graph ref labels and comparison category/endpoints are functional context, not decorative headers.
- Graph paths, commit dots and reference accents use eight theme-aware branch colors from `src/style.scss`, assigned by ref identity rather than lane position. For the same ref set, refresh and appended history preserve colors. Separate names and kind icons distinguish coincident branch tips without inventing ancestry lanes; colors repeat beyond eight refs, so retain full names and accessible disclosure as the authoritative identification.
- Keep active graph edges in persistent lanes until their actual parent row, including siblings with a shared parent. Use rounded horizontal/vertical joins instead of early Y-shaped coalescence. Missing or unloaded parents retain explicit boundary stubs; never imply a root or merge from adjacency alone. Keep the gutter at its intrinsic lane width and contain horizontal scrolling within the graph pane.
- Use 28px subject-only history headers and 40px headers with a reference/status line. Align each dot to its subject band, not the full two-line row. Keep a subdued 14px-high reference summary below the subject; expanded file hierarchies add height below the header without shifting its node or breaking outgoing lanes.
- Show one primary reference per commit, prioritizing its attached HEAD branch, the viewed branch, `main`, other local branches, then remote-tracking refs or tags. Use neutral secondary text with color on the kind icon, and reserve a subtle background for the current branch. Keep fitting names intact and bound long names while preserving distinguishing endings where possible. Show `+N` for every other ref even in wide panes; the count includes hidden remote-tracking refs and tags.
- Hover/focus on the summary or `+N` shows full names grouped into Local branches, Remote-tracking branches and Tags, with explicit HEAD context. Bound large hover previews and offer click/Enter to keep the complete grouped inventory open. Do not show a tooltip over its open disclosure. Escape restores the trigger, Tab continues logical row order, and outside interaction retains the clicked target. Keep focused rows mounted and close stale disclosures on context/snapshot replacement. Reference controls never select commits or perform Git actions. Commit tooltips contain only the subject, exact hash and expand/collapse hint.
- Only the actual resolved HEAD gets a hollow ring and stronger subject weight; ordinary commits, including roots, stay filled. Fold attached HEAD into its matching local-branch summary; preserve standalone detached/repository HEAD context when no matching branch exists. Keep HEAD distinct from expansion selection and keyboard focus. Dot separators and ring centers must match the row's current opaque normal, hover or selected background.
- Default to Cream; offer three light, two gray and one dark interface palette by explicit user choice only, not OS color preference. All palette roles live in `src/style.scss`; keep body, menus, trees, graph and diff controls legible on each palette.
- Use named icons from `src/ui/icons.ts`. Decorative icons are `aria-hidden`; text controls keep accessible names. Do not use unicode glyphs as substitute UI icons.
- Use a single Appearance popover in the top workspace toolbar for coordinated presets and independent interface, syntax and icon choices. Keep the live tree/source sample and presets visible; group detailed choices and original license/source links behind shared UI chevron disclosures. The preview header owns compact Changes / Full file and Scroll / Wrap switchers, not a second theme selector.
- Both source endpoints have equal syntax contrast on the syntax palette's own background, even when that palette differs from the interface. Use full verified endpoint context for grammar state; never dim the old pane or truncate individual grammar lines into partial comment/string state. Preserve source text and aligned reading anchors through view, wrapping and theme changes; virtualize wrapped rows as well as unwrapped rows.
