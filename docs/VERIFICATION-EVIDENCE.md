## Repository-file browsing

The Files-only workspace sidebar progressively enumerates unchanged, changed, untracked, ignored and dotfiles in the actual selected working tree. Git metadata is excluded; symlinks, gitlinks and nested ordinary/bare repositories are opaque. Display paths are never read authority: the renderer activates native-issued file IDs within a retained listing and selected generation/identity. Forged, expired or reselected tokens cannot read contents.

An all-null `RepositoryFilesRequest` starts a listing; continuation carries its issued listing ID plus directory ID and cursor. A null returned cursor completes that directory only, not the repository. The renderer serially pages the root and expanded directories, pauses further reads beneath collapsed folders and discovers every directory in List view. Counts remain explicitly partial until all discovered directories complete; refresh starts a new listing. In-flight replies may complete after a folder collapses, but superseded repository/refresh replies cannot publish.

Same-scope refresh retains one displayed generation while one replacement catches the root and currently expanded branches. Files, directories and listing ID switch together; old rows never acquire the replacement's authority. Collapsed branches do not postpone cutover, and an error leaves the previous listing visible with partial status. The tree remains mounted and restores its leading native-segment anchor from the pre-layout offset even when replacement content shrinks.

Each native page scans at most 256 entries and bounds serialized output to 512 KiB. Traversal retains depth 64, at most 64 unfinished directory streams per listing and eight listing contexts. Targeted literal-path gitlink queries avoid reading the entire index and recheck ancestors before and after content reads. Directory identity/mutation, no-follow traversal, selected generation and existing working-file limits/deadlines remain enforced. A resource limit or expired/mutated continuation is explicit unavailability, never a fabricated complete tree; refresh can restart discovery.

Shared file trees and flat lists use the existing TanStack virtualizer with native-segment presentation keys, logical keyboard order and bounded sticky ancestors. History windows complete commit rows and their existing per-row SVG geometry; expanded files share its scroller. Selected expansion state survives scrolling away, and collapsing an offscreen expansion resets its cached height.

Folder trees start collapsed, including directories discovered by subsequent pages. Opening the repository sidebar initially reads root pages only; explicit expansion requests that directory, while Expand all applies to newly discovered descendants too. Reopening the sidebar preserves the chosen expansion state. Partial progress remains in the loaded-file count without a loading/partial-listing footer; actual errors remain visible. ## Live changed-file monitoring

While either surface is visible, selecting a working tree starts an immediate native scan, then another scan approximately one second after each completion. Scans do not overlap or accumulate timer ticks. Switching contexts cancels the previous scan; selection generations reject stale results, including when the same entry is reselected. The source index timestamp is preserved for Git's racy-index checks, and relevant comparison settings include Unicode filename normalization. Optional locks, fsmonitor and inherited repository-selection overrides are disabled. A scan shares one 30-second deadline. Added, modified, deleted and type-changed paths come from a bounded native `diff-tree --name-status -z --no-renames` read, not a guessed list. A normal commit compares with its first raw parent; merges expose an explicit parent selector; verified roots compare with the empty tree. Missing shallow parents and unsupported native path encoding return honest errors. Commit and parent OIDs are full validated SHA-1/SHA-256 IDs, and an explicit parent must belong to the raw commit. Context/branch/parent changes reject late results. Outgoing graph lanes extend through the expansion to preserve topology.

Committed-file selection uses `reviewCommitFile` and `CommitFileReview` to open the chosen raw parent-to-commit comparison in the shared preview; it is separate from live status authority. Native opaque file IDs bind selection generation, commit, raw parent and validated path. The registry holds at most 64 comparisons and 20,000 files, retaining IDs for repeated expansions. An evicted visible choice renews its exact native listing once before reading with the new ID; display labels only match returned records and never authorize native reads. Root/add/delete absence is explicit, unsupported content and errors never become empty success, and file/parent/context/client changes reject late replies. Selecting a working-file row restores its live comparison. Follow-up browser/service evidence above exercises this newer path; earlier display-only workbench observations and these checks still do not certify native installers or picker behavior.


## Local diagnostics

The native host owns `diagnostics/diagnostics.sqlite` under the same per-user application-data directory as the workspace file. It is not stored in a Git repository or browser storage and is not uploaded. Unix diagnostic directories and files use owner-only permissions.

Records contain timestamps, random session/operation IDs, parent operation IDs, a closed operation/component/event/code vocabulary, monotonic durations, exit status and byte counts. They never contain repository names or paths, file/branch contents, command arguments, process output, credentials, environment values, exception text or stack traces. An expected nonzero Git exit is a process fact; the Git/application layer determines the domain outcome.

The producer does no database I/O and uses a 1,024-entry queue. Write-time retention is bounded to 20,000 events and seven days. Queue exhaustion, incompatible schema, unsafe paths or storage failures report degraded capture without changing repository outcomes. `diagnostic_health`, restricted to the main webview, exposes state, accepted/written/dropped counts and a fixed error code. Shutdown seals native admission and drains owned requests, producers, Git reaping, blocking cleanup and accepted workspace writes before the bounded two-second diagnostic writer drain.

The renderer can submit only fixed, bounded diagnostics; it has no SQL or arbitrary-message endpoint. Request UUIDs propagate through native IPC, application, Git and subprocess scopes. Restoration, recovery, observation and persistence retain parent links; cancellation and supersession are distinct from failure.

Native capture startup can recover an interrupted rollback journal only after a locked, bounded private snapshot rolls back to the exact approved schema and passes SQLite integrity checks. Incompatible, malformed, unsafe or concurrently written stores remain untouched. This recovery does not migrate databases; the diagnostic CLI remains strictly read-only and never performs rollback recovery.

Agents and maintainers must explicitly authorize a local store path. The CLI opens it read-only, validates the exact schema and returns bounded, parameterized event queries; missing/incompatible stores are not created or repaired:

See [DEVELOPMENT.md’s authorized diagnostic CLI workflow](../DEVELOPMENT.md#locate-and-query-the-store) for schema/event commands. Authorize the actual application-data store before querying it; never attach its contents or location to a public issue.

On Windows/Linux, use Tauri's corresponding per-user app-data location. Filters also include `--level warn`, `--component`, `--event`, `--operation-id`, `--session-id` and `--since-ms`; limits are 1–200 and `has_more` makes incomplete results explicit. Use returned operation IDs to inspect a causal chain. Schema/storage failures preserve existing bytes; repair requires a maintainer decision, not automatic deletion.

## Shared verification and Git hooks

Frontend tests live in `tests/unit` and `tests/integration`; Rust tests in `src-tauri/tests/unit` and `src-tauri/tests/integration`. Reusable fixtures live in the respective support directories. Private Rust tests are registered by their owning module, while external integration targets are declared in Cargo.

`npm run verify` runs both builds, unit/integration checks, executable agent documentation and repository policy. `test:unit` and `test:integration` select the same runner's corresponding groups. `.github/workflows/verification.yml` uses the runner on macOS, Windows and Ubuntu. Its manifests retain revision/dirty state, runtime versions, check outcomes, safe behavior identifiers, aggregate counts and exact rerun commands—not raw failure output or private payloads. Missing, skipped or TODO evidence cannot certify a required check.

Native verification uses `.verification/native-target`, separate from Tauri development/packaging artifacts. Rerun commands retain that target explicitly; no stack-size overrides or reduced test parallelism are used.

The repository-local [.agents toolkit](../.agents/README.md) adds explicit worker ownership, delegation/review contracts, checked skills and disposable workflow evaluations. `npm run agents:docs` validates local links and executes the typed SQL instrumentation examples. Deterministic evaluation-grader tests do not claim that agents ran in CI; actual evaluations require an agent to solve the prepared challenges.

`pre-commit` runs repository policy and unit checks; `pre-push` runs full verification. Both block on failure and save evidence under ignored `.verification/pre-commit` or `.verification/pre-push`. Installation does not replace custom `core.hooksPath` or active default hooks. These hooks check the current worktree, not a reconstructed index or pushed revision; CI verifies the checked-out revision. Local hooks remain bypassable and do not replace CI.

## Native-preview evidence

Repository tests, MockRuntime and Chromium are not packaged-native certification. Build an actual unsigned preview with `npm run tauri build`; then assess the artifact and a separate human observation report:

```sh
npm run preview:evidence -- --artifact path/to/preview --platform macos-arm64 --report path/to/observation.json
```

Supported evidence platforms are `macos-arm64`, `windows-x64` and `ubuntu-24.04-x64`. Reports use `schemaVersion: 1`, `boundary: "packaged-native"`, the platform, revision and matching SHA-256 `artifactHash`; human observer/time metadata; OS, architecture, WebView and Git versions; and `installedGit`/`supportedOs` prerequisite statuses. Required scenarios are `install_launch`, `native_picker`, `native_ipc`, `secondary_window_denied`, `repository_open`, `linked_and_bare`, `live_observation`, `read_only_repository`, `diagnostics_correlation`, `diagnostics_privacy` and `diagnostics_health`. Each must have `status: "passed"` and `observed: true`; failed, blocked, missing or not-run observations leave readiness false and exit nonzero.

Reports also require `localization`, keyed by each of `pt-BR`, `pt-PT`, `it`, `es`, `en-US` and `en-GB`. Each locale contains `selection_persistence`, `interface_errors_counts_accessibility`, `native_picker_title`, `repository_data_unchanged` and `linguistic_review`, each with `status: "passed"` and `observed: true` only after the actual human observation. Selection evidence includes System, restart, failed-save feedback and preserved review context. Linguistic review is independent of schema/key coverage. Missing locale cells, failed journeys or unreviewed translations add `localization_unverified` and keep readiness false. These observations are bound to the report's exact native artifact/platform; do not fill them from browser fixtures or generated translations.

The tool hashes the actual artifact and strips private/free-form report details. A validated report is attributed human evidence, not independent certification. Signing, notarization and public-release readiness remain separately unassessed.
